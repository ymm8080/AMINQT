## Part 1: pctChg Analysis

### 1.1 What is pctChg?

- **Definition**: `pctChg = (close / close.shift(1) - 1) * 100` — raw close daily return percentage
- **Source**: Generated by `scripts/pull_bs_extra_fields.py:compute_pctChg_from_v3()`, merged via `scripts/merge_extra_fields_to_v3.py`
- **Panel status**: Already in `data/panel_full_enriched_v3.parquet`, already flows through the build pipeline
- **Auto-processing**: `_add_time_series_changes` already generates `pctChg_chg1..20` and `pctChg_pct_chg1..20`
- **Cross-sectional rank**: Already generates `pctChg_xrank` via `_add_cross_sectional_ranks`
- **IC**: ~0.0043 (weak), ICIR ~0.03, essentially flat in the current registry

### 1.2 Overlap with Existing Features

| Existing Feature | Source Price | Scale | Location |
|---|---|---|---|
| `ret_pct` | close_hfq (adjusteD) | Ratio (0.01 = 1%) | dim03_fundamentals (line 385) |
| `ROC_1d` | close_hfq (adjusteD) | Ratio (0.01 = 1%) | dim01_price_volume (line 229) |
| `pctChg` | close (raw) | Percentage (1.0 = 1%) | Raw column in panel |

**Key difference**: `pctChg` uses **raw close** (what the market actually traded at). In A-shares, stocks undergo ex-dividend, ex-rights, and stock-split events that cause raw close to gap down while hfq-adjusted close remains smooth. The divergence between `pctChg` and `ret_pct` carries information about these corporate events.

### 1.3 Unique Value Proposition

The **divergence** between raw return and hfq-adjusted return is the novel signal:

```
raw_vs_hfq_divergence = pctChg - (ret_pct * 100)
```

- Near zero: normal trading day
- Large positive (pctChg >> ret_pct): raw close rose more than hfq suggests → possible ex-rights recovery
- Large negative (pctChg << ret_pct): raw close dropped relative to hfq → ex-dividend/rights event
- This signal is **orthogonal** to existing price-volume features

### 1.4 Derived Features to Add

**Proposed location**: A small sub-block within `dim01_price_volume` (price derivatives family) or a dedicated short method. Since `dim20_short_horizon` already handles short-term return features, the cleanest approach is to add a `_use_pctChg` helper inside `dim01_price_volume` that computes the unique divergence features.

**Feature formulas** (all per-stock, inside `dim01_price_volume`'s `per_stock`):

```python
# 1. Raw vs hfq divergence (corporate event detection)
ret_pct_daily = g["ret_pct"] if "ret_pct" in g.columns else g["close_hfq"].pct_change()
g["raw_vs_hfq_div"] = g["pctChg"] - ret_pct_daily * 100

# 2. Rolling z-score of raw return (volatility-normalized signal)
pc_mean = g["pctChg"].rolling(20, min_periods=10).mean()
pc_std = g["pctChg"].rolling(20, min_periods=10).std()
g["pctChg_zscore_20d"] = (g["pctChg"] - pc_mean) / pc_std.replace(0, np.nan)

# 3. Tail risk (rolling 95th percentile of absolute return)
g["pctChg_tail_20d"] = g["pctChg"].abs().rolling(20, min_periods=10).quantile(0.95)

# 4. Maximum drawdown within 20d window (fresh to existing features)
g["pctChg_mdd_20d"] = g["pctChg"].rolling(20, min_periods=10).min()
```

**Rationale**: 4 features only. The auto `_chgN` / `_pct_chgN` derivatives already give return acceleration/deceleration. The cross-sectional rank gives `_xrank`. We don't need to duplicate streaks, intraday features, or gap detection that `dim20_short_horizon` and `dim30_kline_geometry` already cover.

### 1.5 NaN Handling

- First row per symbol will be NaN (no prior close). This is identical to `ret_pct` behavior.
- Rolling features need `min_periods` thresholds (10 for 20d windows).
- No missingness flag needed — pctChg near-100% coverage when close data exists.

### 1.6 NEUTRALIZE_COLS / MISSINGNESS_COLS

- `pctChg` itself: NO need for neutralize or missingness. But `pctChg_zscore_20d` and `pctChg_tail_20d` are already scale-free.
- `raw_vs_hfq_div`: Optional addition to `NEUTRALIZE_COLS` if industry effects are suspected, but skip for now — keep minimal.

### 1.7 Protection Against Double Processing

**The `_add_time_series_changes` skip list** (line 116-125) does NOT include `pctChg`. This means `pctChg` will be auto-processed to generate:

- `pctChg_chg1, pctChg_chg3, pctChg_chg5, pctChg_chg10, pctChg_chg20`
- `pctChg_pct_chg1, pctChg_pct_chg3, pctChg_pct_chg5, pctChg_pct_chg10, pctChg_pct_chg20`

**Assessment**: These are NOT redundant.
- `pctChg_chg1` = daily change in daily return = return acceleration (second derivative of price)
- `pctChg_pct_chgN` = (pctChg(t) / pctChg(t-N) - 1) — meaningful when pctChg is near-zero (multiplier effect), but `_chgN` is more interpretable here.
- **Recommendation**: Keep auto-processing. The IC screener will deactivate any auto-derived features with dead IC. No change needed to the skip list.

**Changes needed**:

```python
# Inside the main dim06_valuation_size body (not per_stock), after existing PE/PB logic:

# pcfNcfTTM: P/Cash Flow TTM
if "pcfNcfTTM" in df.columns:
    # Section percentile (like pe_pct, pb_pct)
    df["pcf_pct"] = df.groupby("date")["pcfNcfTTM"].rank(pct=True)
    # Log transform (positive values only)
    df["pcf_log"] = np.log(df["pcfNcfTTM"].clip(lower=0).replace(0, np.nan))
```

### 2.3 dim22_fundamental_pit: 7 Health Ratios

The existing `dim22_fundamental_pit` (lines 1193-1274) processes quarterly financials with QoQ changes, trends, and stability. Add the 7 new ratios following the same pattern.

**Strategy**: Extend the `fin_cols` list and add corresponding outputs. Follow the existing "one col per ratio" QoQ/trend pattern.

```python
# Extend fin_cols and out_cols:
# Add to the per_stock function:

# === New leverage/liquidity ratios (QoQ changes) ===
for col, out in [
    ("quickRatio", "quick_ratio_qoq"),
    ("cashRatio", "cash_ratio_qoq"),
    ("assetToEquity", "asset_eq_qoq"),
]:
    if col in g.columns:
        g[out] = g[col] - g[col].shift(q)

# === New asset quality trend ===
if "tangibleAssetToAsset" in g.columns:
    g["tangible_asset_qoq"] = g["tangibleAssetToAsset"] - g["tangibleAssetToAsset"].shift(q)

# === New coverage ratio (interest coverage, higher = safer) ===
if "ebitToInterest" in g.columns:
    g["interest_cov_qoq"] = g["ebitToInterest"] - g["ebitToInterest"].shift(q)
    g["interest_cov_trend_4q"] = (g["ebitToInterest"] - g["ebitToInterest"].shift(4*q)) / 4

# === New cash flow quality (CFOToNP = earnings quality; CFOToGr = cash realization) ===
for col, out in [
    ("CFOToNP", "cfo_np_qoq"),
    ("CFOToGr", "cfo_gr_qoq"),
]:
    if col in g.columns:
        g[out] = g[col] - g[col].shift(q)
```

**Additional cross-sectional features** (added after per_stock, like `cost50_rank` in dim21):

```python
# Add these after _apply_per_stock:
for col in ["pcfNcfTTM", "quickRatio", "cashRatio", "assetToEquity",
            "tangibleAssetToAsset", "ebitToInterest", "CFOToNP", "CFOToGr"]:
    if col in df.columns:
        df[f"{col}_xrank"] = df.groupby("date")[col].rank(pct=True)
```

Note: `_xrank` is automatically excluded from `_add_time_series_changes` processing (skip_suffix includes `_xrank`), so no double processing.
