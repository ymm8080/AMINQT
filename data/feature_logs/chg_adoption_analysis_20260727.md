## Analysis

### 1. CHG features carry genuine predictive signal
Mean |IC| ranges 0.088–0.100 across all windows — well above the IC_WEAK=0.01
threshold and at or near IC_STRONG=0.03 after considering the full feature set.
CHG features consistently rank in the same signal-strength tier as core features.

### 2. Longer windows do NOT decay — they slightly improve
CHG20 |IC| (0.0996) is **higher** than CHG1 (0.0880), not lower. The signal does
not decay with window length; mid-to-long term changes (10d, 20d) capture
different alpha from short-term (1d, 3d) changes. Both are useful.

### 3. CHG features are COMPLEMENTARY, not substitutes
Base features (e.g. ATR_pct=0.1858) have higher raw |IC| than their CHG
variants (ATR_pct_chg20=0.1001). But they measure DIFFERENT things:
- Base = current level (e.g., "volatility is high now")
- CHG  = rate of change (e.g., "volatility is rising fast")

Tree models benefit from having BOTH perspectives as input columns.

### 4. Mean IC ≈ 0 (near-zero direction) — expected for tree models
The signed mean IC is -0.003 to -0.009 with ~48% positive ratio. This means
CHG features have no consistent linear direction — they capture non-monotonic
patterns that LightGBM (tree-based) can exploit via splits. This is NORMAL
and GOOD for gradient boosting features.

### 5. CHG20 specifically: no reason to exclude
- |IC| = 0.0996, essentially tied with CHG10 (0.0998)
- Across labels: CHG20 matches or beats CHG10 (label_5d: 0.1014 vs 0.1024)
- IC screener will naturally filter any individual CHG20 feature that is dead

## Verdict

**ADOPT.** Keep all five windows `(1, 3, 5, 10, 20)`.

Rationale:
1. All windows show meaningful |IC| ≥ 0.088
2. IC does NOT decay with longer windows — CHG10/CHG20 perform as well as CHG1/3/5
3. Base features and CHG features capture complementary signals
4. IC screener (`ICScreener.screen()`) already evaluates every factor per
   rolling window — dead CHG features will be auto-excluded from training
5. No computational reason to drop CHG20 (same cost as CHG1, just one more
   diff column per source feature)
